# AutoSync Project Description

AutoSync is a Next.js 16 web application that synchronizes Stripe payment data into Google Sheets, providing users with a continuous, automated data pipeline from their Stripe account to a structured spreadsheet workspace. The application enables businesses to maintain real-time visibility of their Stripe transactions (invoices, charges, customers, payouts, subscriptions) in Google Sheets, where they can perform custom analysis, build reports, and create workflows without manual exports or CSV imports. The system uses a guided 4-step onboarding flow: users first authenticate with Google OAuth (via NextAuth), then connect their Stripe account via Stripe Connect OAuth, grant Google Sheets API permissions, create a workspace spreadsheet with protected raw data tabs, and finally configure which Stripe objects to sync before initiating the backfill and ongoing sync process.

The application is built on Next.js 16 with React 19, TypeScript, and Tailwind CSS, using the App Router architecture. Authentication is handled by NextAuth.js with Google OAuth as the primary provider, storing user sessions as JWTs. All persistent data is stored in AWS DynamoDB using a single-table design pattern with composite keys: the partition key (pk) follows the pattern `USER#{authUserId}` and sort keys (sk) use prefixes like `PROFILE`, `STRIPE#{stripeAccountId}`, `GOOGLE#{googleUserId}`, and `SYNC#{spreadsheetId}` to organize user profiles, Stripe connections, Google OAuth connections, and sync configurations respectively. The application uses Zod schemas for runtime validation of all data structures, ensuring type safety and data integrity throughout the stack.

The technical implementation involves multiple OAuth flows and API integrations. For Stripe, the app uses Stripe Connect to obtain OAuth tokens that allow access to the user's Stripe account data, storing the connection metadata (account ID, business name) in DynamoDB. For Google Sheets, a separate OAuth flow grants the application permission to create and update spreadsheets in the user's Drive; access and refresh tokens are encrypted (using a custom encryption utility) before storage in DynamoDB. The sync configuration (`SyncConfig`) tracks which Stripe objects are enabled for sync, the target spreadsheet ID, sync status (syncing, paused, backfill_running, error), and history settings. The application also integrates Stripe Billing for subscription management, handling webhooks for subscription lifecycle events and storing subscription metadata in user profiles.

The frontend is organized into client and server components, with React Query (`@tanstack/react-query`) managing server state and a custom `UserStateProvider` that aggregates user data from DynamoDB (profile, connections, sync configs) and computes an onboarding stage to drive UI flow. The dashboard displays workspace cards showing sync health, last sync time, and enabled Stripe objects, while the onboarding wizard guides users through the multi-step setup process. API routes handle OAuth callbacks, webhook processing, sync configuration updates, and Google Sheets operations (creating spreadsheets, fetching sheet titles). The application assumes a single sync configuration per user for the MVP, with the architecture designed to support multiple workspaces in future iterations. All sensitive operations (token encryption, webhook signature verification, OAuth state management) are handled server-side, with the client primarily responsible for UI rendering and user interactions.
